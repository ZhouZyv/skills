# 作者素材：容器日志踩坑记录

这些是我自己的真实经历，改写文章时可以用：

- 2025 年 11 月某天凌晨收到磁盘报警（95%），上去排查发现 /var/lib/docker/containers 下面某个 json.log 文件 20 多个 G，就是 api 容器的
- 根因：那个服务有段代码在报错，堆栈每秒刷几十行，日志驱动是默认的 json-file，我压根没配轮转——Docker 默认就是不轮转的
- 当时先 echo "" 清了个空（不能直接 rm，dockerd 持有文件句柄，rm 了空间不释放），然后把 compose 里加上 logging 配置，down + up 重建了容器才生效
- 我以为 daemon.json 改了就万事大吉，结果存量容器根本不认新配置，第二次磁盘又快满了才发现这坑——必须重建容器
- 教训：所有生产容器上线模板里默认带 logging 配置，别靠"记得去配"
